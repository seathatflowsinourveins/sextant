# Calibration data job

Trade step: data for calibrated protection widths (D-44, LEAD-2127 §5); also C's morning baseline refresh. Collection never changes a width, places an order, opens a stream, or records a successful calibration trial. Widths stay UNCALIBRATED until the ADR-0019 run is recorded in the cumulative trial ledger.

The user timer runs at 03:00 America/New_York on weekdays, before PRE at 04:00. `parameters.json` records this starting schedule, the reused 20-session window and the existing historical data request ceiling as UNCALIBRATED. XNYS holidays skip before client construction. `Persistent=true` catches a missed timer when the user manager returns; it does not promise a refresh completed before a session. systemd does not start another instance of this oneshot while it is active.

The lead installs and starts the units after merge; this change installs nothing. In the standard checkout at `$HOME/sextant`, copy the `.service` and `.timer` from this directory into the user's systemd unit directory, reload the user manager, then enable/start **the timer**. Never invoke the credential-bearing ExecStart by hand. The unit alone calls `scripts/with-keys.sh --strict`, using C's stored paper data credentials. There is no B client, trading client, account request, live URL or secret file. The script requires the data directory as its argument; neither the script nor the module reads the encrypted store.

Before enabling, stage the reviewed K2 universe artifact as `$HOME/sextant-data/calibration/universe.json`. The job reads its bytes once and uses exactly its symbols; it does not fetch or re-rank a universe. Missing or invalid input refuses before a client is constructed. The existing C runner must be configured to read this data directory's `baselines/` (see `lanes/paper/README.md`); installing this unit alone does not change the running lane's baseline directory. No account handover is performed here.

The job first calls `baseline_recipe.run` for the four verified files and manifest. A flagged baseline preserves the previous active bytes and stops collection. After a baseline succeeds, collection iterates the same prior XNYS sessions and universe, requesting raw minute bars and quotes for SIP's 04:00–20:00 daytime window and BOATS' preceding 20:00–04:00 overnight window. Both feeds and dated `asof` identities stay separate. As in the existing historical fetcher, inclusive request ends are one microsecond before the next boundary; the last submicrosecond of a window is not requested. All received timestamp text, including nanoseconds, remains unchanged. Early-close sessions retain their full extended-hours window.

Outputs, relative to the data directory:

- `baselines/{overnight,pre,rth,post}.json` and `baselines/manifest.json`: the existing schema and manifest-last publication.
- `calibration/{sip,boats}/{quotes,bars}/SYMBOL/SESSION.parquet`: the existing raw response envelope (`page`, `response_json`), including every original page text, conditions and decimals; metadata records the exact window, feed, dated identity and receipt time. Existing partitions are validated and reused, never overwritten. Empty windows have zero rows; they are not usable-width evidence.
- `calibration/runs/SESSION-RUN_NS.json`: emitted only after every partition passes, with file hashes, row/page counts, the universe digest, the actual parameter digest/values, baseline manifest and `survivor_only:true`, `pit_verified:false`. This is input provenance, not a PIT-complete research cohort or a trial-ledger record.

A history failure leaves no completed run receipt. Successful earlier partitions remain for retry; already refreshed baselines retain their own manifest. A later run re-fetches baselines and skips validated history partitions. Failed/flagged services exit nonzero for the user journal. The upstream client aggregates each window and capture keeps its pages in memory; initial history size, completion time and data entitlement need measurement by the lead's installed job. No disk-retention deletion or automatic width qualification is included.

Sources: [Alpaca historical quotes](https://docs.alpaca.markets/us/reference/stockquotes-1), [bars](https://docs.alpaca.markets/us/reference/stockbars), [Python SDK historical client](https://alpaca.markets/sdks/python/api_reference/data/stock/historical.html), [systemd.timer](https://www.freedesktop.org/software/systemd/man/latest/systemd.timer.html) and [systemd.time](https://www.freedesktop.org/software/systemd/man/latest/systemd.time.html), read 2026-11-10. The pinned SDK and proof references are in the manifest's "Morning C baselines and raw calibration history on a user timer" row.
