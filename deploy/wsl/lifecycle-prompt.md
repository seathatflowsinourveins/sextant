Lifecycle sweep for this repository, run by Orca's daily automation in its main checkout. Don't switch this checkout's branch: the lead works here.

1. Run `git fetch --prune origin`.
2. For each worktree in `orca worktree list --json` other than this checkout, find its branch's pull request: `gh pr list --head <branch> --state all --json number,state`. If it is `MERGED`, remove the worktree with `orca worktree rm --worktree branch:<branch> --delete-branch`. Keep a worktree that has an open pull request, has no pull request, has uncommitted changes or has commits that aren't on GitHub, and note why. Also keep a worktree that live work still uses, even after its PR merged: any terminal in `orca terminal list --json` whose `worktreePath` is that worktree, or any running process whose current directory is inside it (`readlink /proc/<pid>/cwd`, proc(5)). An agent can keep working in a merged PR's worktree, and removing the directory under it kills it, as the 2026-11-06 first run did to two lane agents.
3. For each local branch whose upstream is gone, and each branch git kept in step 2, first try `git branch -d <branch>`. This repo merges by squash, and git deletes with `-d` only a branch "fully merged in its upstream branch, or in `HEAD`" (git-branch(1)), so it refuses every squash-merged branch. Then read `gh pr list --head <branch> --state merged --json headRefOid`. Use `git branch -D <branch>` only when that PR is `MERGED` and its `headRefOid` equals `git rev-parse <branch>`, so nothing on the branch is left unlanded. Otherwise keep the branch and note why.
4. If `deploy/wsl/sextant.user-data` pins an older Orca than `gh release view -R stablyai/orca`, and that release is at least 3 days old, move the pin in its own Orca worktree: `orca worktree create --name orca-<tag> --base-branch origin/main`. Use the release's `.deb` URL and the sha256 digest that `gh release view <tag> -R stablyai/orca --json assets` publishes for it. Open the PR with `just pr`, from `.github/pull_request_template.md`, citing `stablyai/orca@<tag>` and its full commit SHA. A later sweep removes that worktree once the PR merges, and the lead then runs `just orca-update`.
5. If `python3 -I scripts/omni_keys.py due` exits 0, run `just omni-keys renew`. It mints each due runtime's replacement through OmniRoute's own CLI, probes the value in memory, seals it into `scripts/keys.sh` and only then revokes the old key by ID, so a rerun converges. A failed probe leaves the old store entry unchanged. For Hermes it first relaunches each old Hermes client through the per-runtime launcher and restarts the shared gateway with `hermes gateway restart --detach`, and revokes only then; a busy gateway refuses, the old key stays, and the next run finishes without minting again. It prints IDs, never a key. [Renewal lesson](../../docs/handbook/omni-keys.md).
6. If you kept anything, renewed a key or opened a PR, comment once on issue #35: what you removed, what you kept and why, and the PR. If nothing changed, post nothing.
