# Native lane runtimes

Issue [#62](https://github.com/seathatflowsinourveins/sextant-archive/issues/62). [Evidence, limits and the devc proposal](../../../docs/research/2026-11-06-native-lane-runtimes.md). `pins.json` records release dates, full upstream commits and binary digests. The runtime pins are the newest releases at least two weeks old at the recorded read; the owner's later instruction explicitly selects the current OmniRoute release.

In the clean Sextant distro, run `just lane-runtimes`. This installs under `~/.local/share/sextant-lane-runtimes`, with commands in `~/.local/bin`. It keeps the existing encrypted store and router data on a repeat install. It checks the owner's 20 GB **MemAvailable** floor before installation. Do not reinstall packages while a router sign-in is in progress.

The one native release binary is Antigravity, verified against GitHub's SHA-256 digest; the router is OmniRoute's pinned npm lock. No `srt` wrapper is installed. Pi, OMP, OpenCode v2, Hermes and the OpenHands SDK were retired on 2026-11-08 under [ADR-0030:36](../../../docs/adr/0030-latest-sota-models.md); their pins stay in `retired_runtimes` and Git. OpenHands is a recorded REJECT, not a pause: AO 0.14.10's adapter drives only its unmaintained CLI, and the re-evaluation report's reopen trigger is a maintained headless or ACP worker with max-effort control, at least 14 days old. Gemini CLI was removed on the owner's 2026-11-06 instruction, verbatim: **"drop gemini, it was not working"**. A host installed before 2026-11-08 keeps the old launchers and prefix directories; this installer neither creates nor repairs them.

## Fresh router

Run `just omniroute` for the durable user service, or `just omniroute status` for its state. `service.sh` uses OmniRoute 3.8.53's own systemd unit generator, retaining notify, watchdog and restart behavior; its startup wrapper injects internal secrets through `with-keys.sh`, and its working directory is the stable main checkout. It binds only `127.0.0.1:22128` and uses its own `router-data`. It never uses the old campaign's :20128–20130 lanes. Provider connections are the owner's browser steps in OmniRoute's upstream credential store, encrypted with the injected storage key. Do not start a second bootstrap server on the service's port.

Open `http://127.0.0.1:22128/dashboard/providers` in an Orca browser tab. The owner sets the dashboard password during onboarding and connects the **GPT/Codex** provider. Never connect a Claude subscription. The installer removes only upstream's public `CHANGEME` first-boot placeholder; it never supplies an owner password.

Create the route once, using the same installed launcher for upstream CLI commands:

```bash
~/.local/share/sextant-lane-runtimes/router-start.sh combo create sextant-gpt --strategy auto --models codex/gpt-6.1-sol-max
~/.local/share/sextant-lane-runtimes/router-start.sh combo list --json
```

`routing.json` declares the combo and endpoint; `model-policy.json` records the owner's model rule, dated Artificial Analysis/vendor sources and the lead-approved Google interim. OmniRoute owns scoring, connection quota and health behavior. The single target pins **gpt-6.1-sol, max** on Codex, the one runtime still on the router. Recorded request artifacts show max on the successful calls; this is not a task-quality benchmark or a measurement of private provider compute. Native Codex subscription headroom is separate from the router's connected accounts.

## Native tabs

Use Orca's known agents, with no task prompt while opening a sign-in tab:

```bash
orca agent launch --agent antigravity --surface terminal
```

Orca supplies Antigravity's `--dangerously-skip-permissions`; explicit upstream denies still apply. It is a native process with the user's filesystem/network access. The retired runtimes have no tab: the installer no longer puts their commands on `PATH`.

AO 0.14.10 (`033d597032e448a0ea16c298350e36b099f74106`) defines `deepseek-harness` in `backend/internal/adapters/agent/deepseekharness/deepseekharness.go:59`: it resolves the bare `dsh` name on PATH (:228-246) and launches `dsh --profile headless` (:144). Select it with an explicit `ao spawn --project sextant --harness deepseek-harness` invocation. `just ao claim <PR>` keeps Codex (`backend/internal/adapters/agent/codex/codex.go:95`) and its Codex-reviewer refusal. `--agent` aliases `--harness` (`backend/internal/cli/spawn.go:224`), so each spawn selects one harness. The keyed `dsh` launcher is tracked in #272; work assignment to dsh waits for evidence once AO takes review-reply loops.

The Google family uses native, owner-authenticated **Antigravity** and OmniRoute's **agy** and **antigravity** provider connections. ADR-0030's model policy applies to those surfaces: **interim: Carbon not in this account's catalog (Google staged trusted-partner rollout)**, with `gemini-4-argon-high` at High until the account lists Carbon. The native launcher selects `--model gemini-4-argon-high --effort high` and documented `AGY_CLI_DISABLE_AUTO_UPDATE=true`; Antigravity reads project `AGENTS.md` directly. agy sessions run `--dangerously-skip-permissions --effort high`: Orca supplies the permissions flag and the launcher pins the effort, never `max`, because `max` silently runs Medium (the Sextant lead's lessons of 2026-11-08/09, C11). Antigravity's explicit deny rules still apply in every mode (the manifest's Antigravity row). If an owner browser step is required, title its tab **SIGN-IN: Antigravity**; the current owner session is already authenticated. The freshness detector owns the later Carbon switch.

Use the main cockpit workspace for persistent runtime/router tabs after the owner finishes sign-ins; the lane worktree can then follow the usual post-merge cleanup. The lead owns that handover, so cleanup must not interrupt a pending browser flow.

## Codex on the router

`sextant-codex` runs Codex CLI 0.167.0 on OmniRoute's pool for Orca and native workers. That Codex is the sandbox's existing pin (the manifest's Runtimes row, installed by `deploy/wsl/setup.sh`), not one of `pins.json`'s release-cooled runtimes: tag `rust-v0.167.0` was cut on 2026-11-05, so the two-week rule above does not cover it. It runs with OmniRoute's own `launch-codex` provider block: `model_provider=omniroute`, `routing.json`'s base URL, `wire_api=responses`, `env_key=OMNIROUTE_API_KEY` and `requires_openai_auth=false`. The model is `sextant-gpt`, the combo the Codex key is restricted to; OmniRoute's credential loop fails a call over to the pool's next Codex connection, and serves it as `gpt-6.1-sol` at `max`. The effort comes from `model-policy.json`. The key is `OMNIROUTE_KEY_CODEX`, injected by `with-keys.sh` and minted by `just omni-keys renew codex`; the same strict hop also carries `CONTEXT7_API_KEY` and `EXA_API_KEY` for the lane MCP set (below); until then the launcher stops at `with-keys --strict`.

- **Home:** `CODEX_HOME` is always `codex-home` in this prefix (mode 0700), never `~/.codex` or an Orca account home; the launcher refuses a home that resolves into one. It drops `ORCA_CODEX_HOME`, stale OpenAI/Codex keys and Claude tokens. Orca keeps worktree trust in its own homes, so the launch folder is trusted for that run only, in AO's `-c projects={…}` form.
- **Sandbox:** `sextant-codex` defaults to `-s workspace-write` and `sextant-codex-review` to `-s read-only`. A caller's own `-s`, `--sandbox`, bypass, `--approve-for-me` or `sandbox_mode` stands. `workspace-write` keeps network off unless `sandbox_workspace_write.network_access` is set, so a writer that pushes needs that or a caller's bypass.
- **Receipt:** after Codex exits, `scripts/omni_receipt.py` reads this run's calls from OmniRoute's call log by the `session_id` header the launcher sends. It writes `codex-receipts/<run>.json` and one stderr line: calls, path, status, served model, connection prefix, the request record's `reasoning.effort`, and `pin_ok`. It never shows a prompt, body or key. A body the size cap dropped counts as `not retained`, evidence neither way: `pin_ok` holds when every call was served by the pinned model and every effort a record kept is the pinned one.
- **Orca:** in **Settings → Agents → Codex**, expand the row and set the binary override to `sextant-codex` (`agentCmdOverrides`). Orca's own Yolo flag then wins over the sandbox default; set Codex to Manual for `workspace-write`. Orca's status hooks live in the home Orca selects, so they do not fire in the lane home, and its account switch has no effect there.
- **AO:** its default worker is `claude-code` (the lead, 2026-11-08: `ao project set-config sextant --worker-agent claude-code --model claude-opus-5-5 --permission bypass-permissions`). AO's Codex harness on the pool is **not supported by AO 0.14.10's account model** (#258). AO reconciles and verifies its Codex accounts by running the `codex` its daemon resolves, against that daemon's own Codex home. With no sign-in there, a Codex spawn is refused. With one, a shimmed Codex would verify a login it never read. So nothing here gives AO this launcher: there is no `codex` name, and `ao.sh` leaves AO's PATH alone.
- **Known limit:** Codex has no catalog entry for `sextant-gpt`, so it runs on its fallback model metadata, as OmniRoute's own recipe does for routed ids. A catalog entry for the alias is a measured follow-up, not part of this path.

## Runtime parity: shelf, MCP set and launch pins

`parity.sh` (the end of `install.sh`, or run alone with `bash deploy/wsl/lane-runtimes/parity.sh` from the main checkout) installs the verified Muse binary from Meta's manifest, the dsh, Antigravity and Muse launchers in `~/.local/bin`, and the keyed `mcp-bridge`. It then runs `parity.py`, which reads `parity.json` and the Claude shelf's own pins in `.claude/shelf.lock.json`. Each runtime gets the 25-skill shelf and the lane MCP set in its own native format, in its own lane home. Nothing goes to the shared `~/.agents/skills`, which blind legs also read; Orca's `orchestration` skill stays where Orca put it.

- **Codex:** the lane `CODEX_HOME` (`codex-home`, the `sextant-codex` home) gets `skills/` and `config.toml` `mcp_servers`, and the hard-lines bundle publishes `rules/sextant-hard-lines.rules` there (`just hard-lines`). Context7's key comes from `bearer_token_env_var`, which fails visibly when unset; Exa's comes from `env_http_headers`, which runs keyless when unset. `sextant-codex`'s one strict hop carries both keys.
- **dsh:** `~/.dsh/skills`. acp and headless link the `config/dsh/mcp` bundle that dsh-tui's research bundle also lists, and `dsh plugin add` initializes acp or headless if it never ran. `config/dsh/mcp/max-effort.cordis.yml`, last in both bundles, puts acp, headless and dsh-tui at max (Rule 2 / ADR-0030): the harness default is only high, and billion-context's own patch otherwise drops dsh-tui's `llm-deepseek` effort pin. Before copying skills or adding plugins, the dsh step requires dsh-tui's recorded `sextant-dsh-research` dependency, installed link and enabled bundle to match this repository. A missing, stale or inactive link is refused with no dsh changes; run setup.sh's documented `dsh plugin --profile dsh-tui add` step for this checkout, then rerun parity.
- **Antigravity:** the Superpowers and `sextant-shelf` plugins, plus `agy mcp add`. Context7 and Exa run only through the pinned bridge, which `antigravity-launch.sh` keys in one strict hop.
- **Muse:** `muse-launch.sh` starts every session with Muse Wonder Full at max and contributor mode off, and refuses contributor mode and `-contributor` models. Muse has one user config root, and `-c` cannot add an MCP server, so its shelf and MCP set wait on #256.

Before writing lane runtime directories, both shell installers run `parity.py --check-roots`. Linked managed roots (skills, configs, profiles, plugin caches, bridge and binary directories), or roots resolving outside their lane, are refused before mkdir, chmod or native calls. Antigravity's native `~/.gemini` config, plugins, plugin-data trees and MCP config join its generated plugin cache in that guard. Each Python writer repeats its own guard. The host `omniroute.service` unit installed by `install.sh` is outside this runtime preflight. ACP/headless count a bundle as installed only when its recorded dependency, installed target and enabled selection all match. A clean shelf cache fetches and detaches at a new lock SHA; tracked, untracked and ignored edits are refused and preserved ([#281](https://github.com/seathatflowsinourveins/sextant-archive/issues/281)).

`dsh plugin add` spawns pnpm from PATH. `parity.sh` puts setup.sh's host-tools pnpm 11.21.0 (`deploy/wsl/dsh/package-lock.json`) first and stops before any change if pnpm is missing. Every Sextant dsh launch, the headless legs included, calls `sextant-dsh`, the keyed launcher's own name, so it needs no PATH order (#255's pattern). AO 0.14.10's deepseek-harness adapter resolves only `dsh`, so the launcher is linked as `dsh` too. That bare name needs `~/.local/bin` ahead of sextant-agents' own unkeyed `dsh`. Orca writes its caller's PATH into its unit, so `update-orca.sh` and setup's first `orca-ide serve` put `~/.local/bin` first, as `sextant.user-data`'s login PATH does. dsh-tui never runs a shell launcher (its locator runs dsh's JS entry), so an agent starts it with `scripts/with-keys.sh` (docs/start.md). Playwright and CodeGraph are opt-in jobs in every runtime. A lane file or skill that differs from the pinned render is kept and reported, and the script exits non-zero. Relaunch lane sessions at a safe checkpoint; dsh hot-reloads profile patches into running sessions. Native listings are in [parity-receipts.json](parity-receipts.json).
