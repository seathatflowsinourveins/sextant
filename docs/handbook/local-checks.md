# Local checks lesson, 2026-11-07

The billing outage on #53 showed that a fallback PR cannot repair its own base-branch checks. Prove runner routing through an existing dispatchable workflow on the PR branch before asking the lead to sequence a bootstrap landing. GitHub's [workflow dispatch](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow) and [self-hosted routing](https://docs.github.com/en/actions/reference/runners/self-hosted-runners), read 2026-11-07, supply those mechanisms; [the runbook](../../deploy/review/README.md) carries the operational rule.

Docker's environment configuration is retained in container metadata. Stream the JIT input over stdin and export it inside the container; the runner's own files still require temporary memory-backed storage and cleanup. Keep the distinction between a fresh runner and an agent-free host: JIT cannot make this host's passwordless-sudo agents unable to forge a verdict. Native logs and receipts are evidence with that limit.

Split the runner by what a job may touch, not by workflow. PR code goes to a label with no Docker socket, API or shared network, because a socket mounted for one trusted job is equally available to the next untrusted one. Give that profile its own user-defined bridge: Docker's default bridge lets containers reach each other, and gh-aw puts its MCP gateway there. Measure the isolation on the real daemon (#201); a design argument alone is not enough: a port another job publishes without an address answers on every bridge's gateway until the daemon binds such ports to loopback, and a bridge reaches the LAN, the tailnet and host listeners until private ranges are dropped. Run jobs as the image's non-root user, as hosted runners do: a root job breaks tools that refuse root and gh-aw's chroot identity. Start each slot once after any host hardening and before the push: a root-owned `DOCKER_CONFIG` broke buildx's build-cache prune, which only the docker slot's cleanup runs, and the slots were stopped. gh-aw expects a runner and its daemon to share one `/tmp`: its setup deletes `/tmp/gh-aw`, and its MCP gateway mounts `/tmp` through the daemon. A bind mount at `/tmp/gh-aw` failed the first review-proof run, and a per-job link failed the second, so docker jobs share the host's `/tmp` and the slot sweeps it. Let gh-aw detect the socket's group; a forced 0 locks out its non-root gateway. Keep `$HOME` the parent of the job's mounts, as on ARC: AWF's arc-dind sandbox has no home of its own (the third run). AWF mounts the daemon's `/tmp` into every agent, and a rootless daemon's `/tmp` is the host's. Run the real workflow before landing a runner change; each review-proof run found one of these. A branch dispatch runs the branch's own workflow file. Main-gate the repository's own trusted-profile jobs, through `pull_request_target` or exact `github.ref` conditions. A new branch workflow can still request the label, because a user-owned repository cannot restrict a label to selected workflows, so no collaborator is added first.

A JIT runner's steps run as the runner's own user, so they can read its one-job credentials; upstream offers no in-container isolation short of ARC's Kubernetes pod split. Record such a residual precisely and take it to the owner, instead of writing it off as accepted. Enable each slot at boot with lingering. User managers cannot order units across accounts, so wait for the daemon locally, with a bound.
