# Native runtime installation lessons

Source: issue [#62](https://github.com/seathatflowsinourveins/sextant-archive/issues/62), the [pinned adoption evidence](../research/2026-11-06-native-lane-runtimes.md), and the upstream files named there. Applied by the native installer, profiles and launch commands in `deploy/wsl/lane-runtimes/`.

- A successful Orca launch receipt proves a terminal was created. Inspect readiness separately: provider/model arguments, native onboarding and owner browser sign-ins can still stop it.
- Inject keys in the command Orca actually starts. Keying the `orca` CLI client does not key a process launched later by its server. Native configs reference an environment name; the launcher's `with-keys.sh` supplies the value to one runtime only.
- Keep approval bypasses with their owning upstream: Pi needs no extra per-tool flag; OMP and OpenCode need explicit launch choices because Orca 1.4.251 does not add theirs. Keep explicit upstream denies.
- A release pin needs its native updater setting too. Antigravity replaced its binary on first startup; set its documented `AGY_CLI_DISABLE_AUTO_UPDATE=true` before launch, then recheck the actual executable version.
- Retire the whole integration when the owner drops a runtime. On 2026-11-06 the owner said **"drop gemini, it was not working"**: remove its dependency, launcher, installer changes and active manifest row, retaining the words and pin only in history. The Google family remains native Antigravity and the fresh router's agy/antigravity connections under ADR-0030; Gemini CLI's failed sign-in is no longer an acceptance requirement.
- Native daemons outlive a keyed command. Hermes's shared gateway retains its launch credential, and an old TUI can win the restart race with the old key. Relaunch those clients, then restart through the current per-runtime launcher; coordinate this with key renewal before revocation. Never solve it with an API-key argument or plaintext file.
- CLI option scope matters: OpenCode v2's one-shot command accepts `run --standalone --auto`; putting those options before `run` fails before inference. Verify the actual subcommand used by automation.
- Apply lifecycle scripts selectively. Pi documents an install without dependency scripts; OpenCode's exact-version native binary requires its postinstall. A placeholder that answers neither `--version` nor a real launch is not an installed runtime.
- Provider connections, native subscription headroom and a runtime's model picker are different signals. A leaderboard entry is not proof that an account has a model. Record the owner's intended model, authenticated catalog and explicitly authorized interim separately; Carbon High remains pending staged access here.
- Correlate exact smoke replies with per-runtime key attribution and saved request artifacts. A synthetic stream model label or empty summary-effort column is insufficient; the OpenHands/final Hermes artifacts recorded max while their summaries were null. This proves an outgoing request, not private provider compute or task-quality merit. Retain failed attempts and cancellations.
- A dashboard's working count is not a dispatched-process count. Inspect native hook presence and live events before editing managed account/profile configuration; both Codex and Claude report from their isolated Orca homes at this pin. A later snapshot cannot establish the precise cause of an earlier display.
- Match a header name byte for byte across two upstreams before attributing calls by it. Codex 0.167.0 sends `session-id`; OmniRoute 3.8.53 records `session_id`. The J1 smoke's empty client session was that mismatch, so `sextant-codex` sets the provider header itself.
- A launcher that pins its own `CODEX_HOME` leaves its host's per-home state behind. Orca's status hooks and worktree trust live in the home Orca selects, and AO's Codex launch gate reads that home's sign-in. AO 0.14.10 also verifies its Codex accounts by running the `codex` it resolves, so a PATH shim that swaps `CODEX_HOME` would verify a login it never read (#258). Never give a host's own Codex name to a lane launcher. Trust the launch folder per run, as AO's own launch does. Record what a host cannot follow; never copy its files into the lane home.
- Retain a real upstream gap. OpenHands SDK is programmatic and has no native Orca ID at this pin; a plain-terminal SDK example does not change the registry.
- Refuse redirected managed roots before the first installer write, including chmod and native plugin calls. A safe final skill destination does not make its symlinked `skills/` parent safe. Both shell installers run parity's read-only root preflight; each Python writer checks its roots too. Check a bundle's installed target and enabled selection as well as its manifest dependency. Refresh a clean shelf cache by fetching and detaching at the exact locked SHA; keep tracked, untracked and ignored edits. These are [#281's three findings](https://github.com/seathatflowsinourveins/sextant-archive/issues/281), applying the existing Codex `readlink -m` guard, dsh plugin-manager contract and Git's `git-fetch(1)` / `git-checkout(1)` semantics.
- Owner sign-in tabs need stable cockpit placement before the task worktree retires. Keep their titles clear, never print authentication URLs or credentials into an issue, and let the lead hand them over without interrupting a browser flow.
