# qmd retrieval on this repo: keyword lookups land, plain-language questions miss (#113)

This record measures the adopted repo retrieval, `qmd search` (BM25 only, no model), on Sextant's own `docs/` and `lanes/` corpus. It settles the "retrieval quality on this corpus: not measured" line in the manifest and ADR-0022. It measures retrieval only; it claims no trading merit and adds no trial.

## Method, all upstream

- The harness is qmd's own `bench` at tobi/qmd@v2.8.3 `facd35e01359e59d938bc9418e93fb9318addee3` (`dist/bench/bench.js`, `score.js`; README "Benchmarking", read 2026-11-06). It reports precision@k, recall@1/3/5, MRR and F1 per backend against a fixture of queries with known-relevant files.
- `runBenchmark`'s own `backends` option limits the run to `bm25`, so no model is fetched. The CLI's `qmd bench` always tries all four backends, and `vector`, `hybrid` and `full` would need the embedding, generation and rerank models that ADR-0022 keeps OFF. `just qmd-bench` makes that call against the committed `.qmd/index.yml` after `qmd update`.
- [The fixture](2026-11-06-qmd-bench/fixture.json) (SHA-256 `c43e153cedee7965057444fdd6607f0ec006dc38d48a4110f2ed8766cdd4d07a`) was fixed before any run. It holds 30 lookups an agent makes here, each naming the document that answers it: 15 typed `exact`, which use the terms an agent types into `qmd search`, and 15 typed `semantic`, which ask the same kind of need in plain words. A lead-written gold set has one author's bias. A wrong gold file would lower a score, never raise one.
- [The raw result](2026-11-06-qmd-bench/bm25-result.json) (SHA-256 `93a44b435513c4cf4feb491effb4d81df73eeef6d4f71a3f8a68b3b86e9e7c79`) comes from qmd 2.8.3 (facd35e) on the clean distro, Node v24.22.2, with 69 documents indexed at `ce1b6d8`, on 2026-11-06. The run wrote nothing under the caller's XDG config or cache.

## Result

| Query set | n | R@1 | R@3 | R@5 | MRR | Expected file in top k | No result at all |
|---|---:|---:|---:|---:|---:|---:|---:|
| Keyword (`exact`) | 15 | 0.933 | 0.967 | 1.000 | 0.956 | 15 / 15 | 0 |
| Plain-language question (`semantic`) | 15 | 0.100 | 0.133 | 0.133 | 0.167 | 3 / 15 | 5 |
| All 30 (qmd's summary) | 30 | 0.517 | 0.550 | 0.567 | 0.561 | 18 / 30 | 5 |

Average latency is 2 ms per query. Every keyword lookup lands. The one below rank 1 is `memsearch`, where the DeepSeek memory leg outranks the convergence record that rules on it. Questions phrased in words the documents don't use mostly miss. For example, "can the bot cancel or resize an order the owner placed himself" returns nothing, although ADR-0007 is the answer. The three that land (`q-options`, `q-start`, `q-chart`) share a rare term with their answer, such as "option", "WSL" or "chart".

A re-run on this branch, with this record indexed, reproduced every score. Only lower ranks moved: this record quotes `q-owner-orders`, so the record itself is now that query's only hit.

## `qmd update` rewrote the tracked config

The first run left `.qmd/index.yml` modified. On every CLI run, qmd's `ensureModelsConfiguredForCli` (`dist/cli/qmd.js` at the pin) saves the built-in default model URIs into a config that lacks them, and drops the file's comments. So any agent that followed the manifest's "run `qmd update`" dirtied the checkout. `dist/trust.js` says built-in default URIs need no trust approval. `.qmd/index.yml` now carries exactly that `models:` block, so `qmd update` leaves the file byte-identical. Listing the models loads none of them: `search` stays BM25 and writes nothing under the caller's XDG config or cache. `test_qmd.py` checks the block against the defaults and checks the bytes after `qmd update`.

## What it means for use

This gap is the documented boundary of the mode we adopted, not a defect. qmd's bundled skill at the same pin (`skills/qmd/SKILL.md`, "Pick the right search mode") says: use BM25 "when you know exact words, titles, names, code symbols, or rare phrases". When the user "uses different wording than the source", write the `lex:` terms yourself or use `qmd query`'s semantic fields. The research lane's README now says to search with the source's own terms, not a sentence.

## Not measured

- The `vector`, `hybrid` and `full` backends. They need `qmd embed` and model downloads, which ADR-0022 keeps OFF. Turning them on is a separate, sourced proposal; this fixture is ready to score them.
- An agent rewriting a question into keywords before `qmd search`. Measuring that would need gold-blind rewrites, which this run doesn't have.
- The Mac install and the sandbox image's run of the same fixture.
