## Orca dashboard investigation

The issue's dashboard addition asks why one working row was shown while twelve workers were dispatched. At the mandated Orca pin, [agents/sessions documentation](https://github.com/stablyai/orca/blob/a162e08b29b2883b02d8a0dfcc99e26c80b2cfe7/docs/site/content/docs/model/agents-sessions.mdx) and `src/renderer/src/components/dashboard/build-dashboard-snapshot.ts` derive the board from native pane status, OSC-title observations and orchestration projection; the working bucket counts current turns rather than dispatched processes. Idle rows are hidden unless `experimentalAgentDashboardShowIdle` is true. Subagents fold into their parent card. Dispatch count therefore cannot by itself establish missing telemetry.

Codex's `src/main/codex/hooks/installation/codex-hook-local-install.ts` installs `hooks.json` and matching enabled trust entries in the exact launch home, including a managed account's `CODEX_HOME`. Its nine native events include SessionStart, UserPromptSubmit, Pre/PostToolUse, PermissionRequest, Stop, Interrupt and subagent lifecycle. `src/main/claude/hook-service.ts` installs native event hooks into explicit `CLAUDE_CONFIG_DIR` profiles; profiles inherit the default status line. The common hook server feeds renderer status through `src/renderer/src/hooks/ipc-events/agent-status-ipc-bridge.ts`. [Orca's Codex docs](https://github.com/stablyai/orca/blob/a162e08b29b2883b02d8a0dfcc99e26c80b2cfe7/docs/site/content/docs/agents/codex.mdx) name a real failure mode: a wrapper overriding an existing `CODEX_HOME` bypasses the prepared home. This worker's runtime launchers do not wrap Codex.

Value-free local inspection on 2026-11-06 found all nine managed Codex trust rows enabled, the managed hooks present since 13:37 UTC, and native Claude hooks/status lines in both default and managed profile homes. Orca's `agent-hooks/last-status.json` held **9 Codex and 11 Claude source entries**, including this worker's current PreToolUse and recent PostToolUse events, plus completed Stop/permission/subagent events; native terminal discovery recognized the running Codex/Claude panes. Thus managed account/profile paths do report here. The earlier one-row view cannot be reconstructed from this later snapshot; current evidence does not show a missing-hook configuration to repair. Its count may reflect the current-turn/idle/filter semantics above; that is an inference, not a claimed reproduction. No speculative host settings change is made.

## Proposed devc scope, for the lead

Leave `AGENTS.md` unchanged in this lane. [Trail of Bits' pinned README](https://github.com/trailofbits/claude-code-devcontainer/blob/062e9e778d6255a87d55452f8a546240a28f67f3/README.md), read 2026-11-06, describes containment for bypass-mode security audits/untrusted code and cross-engagement leakage. It does not establish a universal requirement that every unattended process in a dedicated, trusted project must use `devc`. Its threat model also states the limits of containment, including deferred host execution and credential exposure inside a container. [Pi's pinned README](https://github.com/earendil-works/pi/blob/4a080252f06caf63a525d7873c5d94d3c23887e0/README.md) documents native user permissions and containerization when stronger boundaries are needed. Orca's pinned supported-agent page likewise distinguishes a worktree from a security sandbox.

Proposal: **require `devc` for bypass-mode work on untrusted code and on machines shared with other work; allow trusted, supervised or unattended Sextant tasks as native tabs on this owner-dedicated distro unless the selected upstream runtime/job explicitly requires a container.** Keep the current container recipe for those cases and for container-specific proofs. This is the proposed policy derived from the owner direction and upstream threat model, not an upstream claim that native execution has equivalent containment. The lead lands any instruction change. All secrets/live/custody/one-writer hard lines remain.
