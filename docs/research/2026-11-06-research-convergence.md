## Agent-memory disagreement, resolved by separating the requirements

At [memsearch v0.4.23](https://github.com/zilliztech/memsearch/tree/65d8b220d4265f70441785aa22203f0e85ea3ec6),
`65d8b220d4265f70441785aa22203f0e85ea3ec6`, README and the native
`plugins/{claude-code,codex,dsh}/` paths establish all three local integrations.
The dsh README describes completed-turn capture and a recall reminder/skill;
the Claude hooks include synchronous startup/prompt hooks and asynchronous
capture. Markdown journals are canonical relative to its derived index. These
are documented mechanisms, not a measured local install or capture-quality result.

**Claude/DeepSeek's local pick and GPT's “none complete” answer can both hold.**
Committing Markdown makes it transportable, but is not automatic GitHub push,
pull, cross-device conflict handling or complete automatic recall. The DeepSeek
leg itself concedes the strict reading is unmet; its “native GitHub transport”
language means files can be committed, not that transport happens uninvoked.
The raw reports stay intact; no unanimous complete solution is claimed.

**Decision:** record memsearch as a local candidate; install no capture layer
and build no sync hook. No owner exception for session-end `memory/*` pushes is
assumed. Existing native memory and reviewed repo lessons remain in place.
Milvus shared-writer behavior, background cost, model freshness/host support
and exact recall behavior require their own source/install receipts before any
future adoption; the screens' old summarizer defaults are not Sextant defaults.

At [qmd v2.8.3](https://github.com/tobi/qmd/tree/facd35e01359e59d938bc9418e93fb9318addee3),
`facd35e01359e59d938bc9418e93fb9318addee3`, README and `src/mcp/server.ts`
document lexical search, source reads and a derived local index. Native
`qmd search` is the small-footprint repo-document selection. MCP `query` must
use explicit lexical subqueries and `rerank=false`; ordinary hybrid query can
load models. Skipping embedding alone does not make every API model-free.
This source-backed role selection amends ADR-0022; install, WSL/Mac operation
and target-corpus retrieval quality remain **unverified**. OpenViking retains
the owner's enhanced-dsh role; no claim here admits it to blind contexts.

Compounding remains reviewed repo records. `ce-compound` and scheduled
reflection can feed that process; they do not create a second canonical store
or authorize automatic handbook writes by this worker. #53 owns automation;
the **Lesson** in this PR body goes to the lead's ADR-0018 single writer.
