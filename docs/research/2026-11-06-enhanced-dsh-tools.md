Read and checked 2026-11-06. This implements the G2 brief, not an installation on the old host. The canonical selection, pins, application files and one proof per pick are in [the manifest](../manifest.md). No trading endpoint, sign-in store or existing local service was contacted.

The owner defined the scope:

> "we need to using full sota harness framework.dsh that is fully enhanced with openviking etc"

> "please land them cleanly into the repo and the new wsl , as least the fully enahcend harnessed ecosystem"

Here, fully enhanced means the requested native composition is supplied: Context7, Exa, DeepWiki, paper-search, Brooks, reference-checker, session-search, billion-context and explicit synthesis OpenViking. It does not mean the clean distro has run or earned a retrieval-quality result. The brief explicitly prohibited installing or executing downloaded packages on this host.

## Receipts and limits

The old `config/dsh/plugins.lock.json` activation record distinguishes reviewed maps/digests, profile package installation, provider startup/catalogs, network containment witnesses and provider retrieval outcomes. It explicitly did not prove retrieval outcomes or managed-home jobs. This change preserves that distinction:

| Receipt | What this branch establishes |
|---|---|
| Sources/configuration/digests | Re-read pins, integrity/provenance checks, native composition files and local configuration proofs |
| Public provider contract | Anonymous MCP initialize/tools/list here: DeepWiki's three tool names above; Context7 advertises `resolve-library-id`, `query-docs`. Both negotiated `2025-11-25`. These are service metadata, not dsh startup receipts |
| Exa availability | Anonymous initialize returned HTTP 403. Its documented optional `EXA_API_KEY` header is configured, but authenticated startup and search/fetch are **unverified**. No silent success or substitute provider is claimed |
| Clean installation | **Unverified:** cloud-init boot, root packages, native profile, hook execution in the new distro, rerun behavior and complete transitive runtime resolution |
| Active dsh/TUI inventory | **Unverified:** actual `dsh --profile dsh-tui --dump-config`, TUI launch in Orca, native sign-ins, installed tool/skill inventory and the runtime DeepWiki mask |
| Local retrieval | **Unverified:** image/model download and load, service readiness, actual repo-copy import, `find` followed by reading a returned `viking://` URI, citation usefulness and index rebuild after mutation |
| Old confinement witnesses | Not carried over: no old srt jail, relay, per-child Keychain policy or old-host receipts are asserted for the owner's new native WSL environment |

OpenViking exposes write/edit/forget, session and administrative operations through its MCP, without a documented per-tool allowlist at this pin. Workflow intent is not enforcement. Only a fresh committed `docs/` COPY is imported with `vectors_only`, empty reason and watch interval zero. Rebuild a fresh workspace if it changes; the repo remains canonical. The native reference checker and session search also remain synthesis-only. Their residuals are not new security gates.

`bash -n`, ShellCheck, cloud-init schema, YAML/Compose parsing, ruff, targeted pyright and the scoped pytest suite are recorded with exact commands/results in `../REPORT.md`. The schema command reports a valid schema but warns that this worker cannot read the old host's cloud-init instance pickle/datasource; no permission change was made. Full `just ci` and container-only/host-mutating proofs are **unverified** because host installs and service changes were prohibited. Revisit on upstream releases, a changed tool inventory or a failed clean-distro receipt, not a calendar date.
